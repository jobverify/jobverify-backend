# Local description generation on CPU

[LFM2.5-1.2B-Instruct QAD Q4_0](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct-GGUF/blob/430bea1a9fa4d973ce789c15f15e9ed214846f4f/LFM2.5-1.2B-Instruct-QAD-Q4_0.gguf) is the production description model. Its immutable revision, 695,755,488-byte artifact, SHA-256 and llama.cpp b11146 CPU runtime are pinned in [model.json](model.json). The worker verifies pinned assets before startup. Generation runs on the Actions runner without a paid inference API.

Policy `job-description-prose-v17` uses actual LLM rephrasing of scraped employer text. The model improves wording, headings and bullets using only supplied source information. Production has no application-level input/output word, character, byte or fact-count ceiling, and no minimum source word count. Blank or markup-only source remains ineligible. The older fact-plan, evidence-text, source-section and bounded-edit protocols remain available to explicit callers and regression tests; their limits do not govern production prose rewriting.

The client cleans source markup while preserving comparison operators, numbers and text. It counts the actual local chat template with the model tokenizer and reserves room for output inside each 8,192-token context. Each generation can use all remaining context headroom, rather than a fixed 768-token or 1,536-token prose ceiling. Inputs that do not fit, and outputs stopped by the context limit, are split near paragraph, sentence or word boundaries and retried. Splits preserve the entire source and Unicode characters. The nearest recognized source heading supplies section context to later fragments. All chunks share the remaining workflow budget; production has no separate 180-second description deadline. Explicit callers can still request a shorter timeout.

Only a complete sequence of rewritten chunks can publish. Final validation verifies the source hash and reconstructs the entire cleaned source from the chunks, rejecting missing suffixes. Per-chunk checks preserve numeric sequences, URLs and the presence of required/preferred and negative scope. Scope checks also reject shared substantive terms moving between required and preferred source statements, both per chunk and across the combined output. These structural checks do not prove semantic equivalence, complete factual retention or absence of hallucination. Model prompts require preservation of all details, actors, conditions and factual relationships; representative native output still needs quality review. No perfect-coverage or zero-added-claims score is asserted for prose.

Accepted prose becomes Markdown in description through the existing escaped renderer. Original sourceDescription, hashes and employer/filter fields are preserved. Canceled or incomplete work cannot replace the visible source. Physical model context, workflow time, memory and database document constraints still apply. Long documents may require many sequential generations and actual prose rephrasing costs substantially more inference than compact category decisions.

## Actions budgets and resume

The workflow uses **one GitHub job, one model server, four CPU threads and four concurrent rewrite requests**. Each slot has an 8,192-token model context. The prompt-cache cap remains 128 MiB. Context size bounds each individual request, not the total description length; sequential chunks allow aggregate input and output beyond that window.

JOB_DESCRIPTION_REWRITE_CPU_THREADS and JOB_DESCRIPTION_REWRITE_CONCURRENCY are capped at available CPUs up to four. Local callers still default to one request unless concurrency is explicitly enabled. Pipeline throughput must be measured on the actual runner; rephrasing does not guarantee that every queued job will publish within the workflow budget.

Scraping, generation and classification run in separate workflows. Generation has a 350-minute job limit, a 345-minute step limit and a default 19,800-second (5 hours 30 minutes) total runtime budget including setup. Cleanup retains two minutes before the job deadline. JOB_DESCRIPTION_REWRITE_BUDGET_SECONDS overrides the total budget within that deadline; JOB_DESCRIPTION_REWRITE_MODE=off disables generation. An empty queue skips model cache restoration and startup.

A normal rewrite budget stop completes the pipeline stage and permits classification to continue with pending descriptions using their employer source. The summary still records budgetExhausted and interrupted work. Explicit cancellation remains incomplete; nonzero exits, worker/code/database errors and stale guarded writes remain failures. This does not override a GitHub job timeout or external cancellation.

The MongoDB queue reader materializes eight jobs per short indexed query and advances by _id. Each query finishes before inference; no database cursor remains open during multi-minute rewrites. Failed page reads still propagate as database errors. Source hashes, attempt counts and guarded updates retain the durable queue behavior. Interrupted work stays pending; transient item failures retry after one hour, up to three attempts. A changed source displays the latest employer text until its replacement passes. Model/policy changes do **not** automatically requeue published descriptions, unchanged historical records or old skipped records.

## Cache and diagnostics

LFM uses separate Actions keys for immutable assets and accepted prose rewrites. Validated outputs are cached in .cache/description-rewrites under policy v17. Cache identity includes the model, full policy configuration and source input hash. Cached rewrites are revalidated against the complete current source. Old fact-plan caches cannot become prose output. Memory caching is bounded to 128 entries; there is no per-description cache text ceiling.

Summary artifacts and console results omit source/completion bodies and report configuration, warnings, token use, latency, memory and queue progress. Bounded-edit-specific metrics only apply to callers selecting that protocol.

A separate description-rejections.json artifact contains at most ten rejected examples, capped at 64 KiB, with at most two samples per reason. A new rejection reason can replace a duplicate-reason sample when the set is full. Bounded raw completion previews survive partial JSON parsing and incomplete streams; failing section/item details are included when available. It excludes exception messages and configuration objects. The summary contains reason counts and the sample count, not those text excerpts. These examples follow the existing 14-day Actions artifact retention and repository access rules.

The generic publishing filter rejects missing, blank and empty-HTML employer descriptions before persistence. Historical empty-description records are hidden from public lists, detail pages, saved-job results and counts. An explicitly empty source cannot be replaced with generated display text. Scraper diagnostics retain filteredEmptyDescription, and raw dry-run captures remain available for inspection.

## Validation status and optional tools

Native prose inference quality and full-queue capacity have not been benchmarked for v17. Local HTTP tests verify transport, chunking, validation and publication behavior using mock completions. Existing historical model results do not establish the new prose throughput. See [BENCHMARK.md](BENCHMARK.md) for historical measurements.

Existing commands remain descriptions:preview (queue count), descriptions:rewrite (queue publication), and descriptions:benchmark (20 source jobs, no MongoDB). The optional native smoke test is test/qwenDescriptionWorker.integration.js; it requires predownloaded verified assets through DESCRIPTION_SMOKE_ASSET_DIR. The optional one-versus-four-slot comparison is separate from production defaults. Do not run these locally unless requested.

The full dry-run benchmark defaults to --model 9000 and the configured production client. Local source/output reports and resumable evaluations reject changed model/policy/source identities. Experimental trial prompting is documented separately in [TRIAL.md](TRIAL.md); it is not the production publication protocol. Windows speed and earlier model results do not establish Ubuntu throughput.
