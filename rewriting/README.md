# Local description generation on CPU

[Qwen3.5-9B Q5_K_M](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/blob/dcb5858fb5302827076259ceafff1690cb56d736/Qwen3.5-9B-Q5_K_M.gguf) is the production description rewriting model. Its immutable revision, 6,577,841,376-byte artifact, SHA-256 and llama.cpp b11146 CPU runtime are pinned in [model.json](model.json). The worker verifies the pinned assets before startup. Generation runs locally on the Actions runner without a paid inference API.

Policy v14 asks Qwen for at most two edits of 160 printable ASCII characters each, chosen from at most six job-focused source statements of up to 320 characters. Company-history sections are excluded from this small prompt, while the complete source inventory remains available to the renderer. Edits must retain source actors, actions, conjunctions and factual words in order, including repeated terms; shortening away details rejects the completion. The renderer resolves evidence from the original input and preserves existing section scope. Numeric facts, conditions, negation, qualifications and metadata are copied verbatim. Unscoped statements remain in the overview. Original Unicode text is retained independently of the ASCII limit on generated edits. Short original bullets and up to 64 rendered items per section are supported; larger sections are skipped before inference. Thinking remains disabled, and missing employer information is never invented.

When no eligible edit candidates exist, the renderer can produce validated sections directly from source with no inference. Summary counts distinguish these publications and report model-edited versus source-copied items. Company history is filtered from the model prompt only; it is still preserved in the rendered source inventory.

Validation checks evidence, unsupported terminology, numeric relationships, negation, conditions, required versus preferred scope, repetition and coverage of parsed requirements and responsibilities. Numeric, negated and conditional source statements retain their exact wording. Factual terms retain their relative order to reject reversed relationships. These conservative checks can reject useful paraphrases, and they do not prove semantic entailment. Review pipeline samples against their original source before judging quality.

Accepted sections become Markdown in description, using the existing escaped heading/paragraph/list renderer. Original sourceDescription, source hashes, employer fields and classification fields remain preserved. Classification prefers a validated current rewrite and otherwise uses the original source. Rejected, truncated or timed-out individual rewrites retain that source, record warnings, and let the pipeline continue. Worker crashes, code errors and database failures remain fatal.

## Actions budgets and resume

The workflow uses **one GitHub job, one model server, four CPU threads and one active rewrite request**. Its context is 8,192 tokens, with a 128 MiB prompt-cache cap. Output starts at 1,024 tokens; full source details are retained independently of this generation cap. Token truncation can retry once up to 2,048 tokens. A retry is skipped when measured generation speed indicates it cannot fit the remaining deadline. Prompt sizing and both attempts share the original 600-second request deadline, with a 64-token context reserve. Sources with less than 256 tokens of output headroom are skipped without inference.

JOB_DESCRIPTION_REWRITE_CPU_THREADS and JOB_DESCRIPTION_REWRITE_CONCURRENCY select thread and request counts, each capped at available CPUs up to four. Higher concurrency is an explicit comparison option, not the initial Qwen workflow setting. It increases memory/context allocation and needs separate measurement on the target runner.

Scraping, generation and classification run in separate workflows. Generation has a 350-minute job limit, a 315-minute step limit and a default 18,000-second total runtime budget including setup. Cleanup retains two minutes before the job deadline. JOB_DESCRIPTION_REWRITE_BUDGET_SECONDS overrides the total budget within that deadline; JOB_DESCRIPTION_REWRITE_MODE=off disables generation. An empty queue skips model cache restoration and startup.

A normal rewrite budget stop completes the pipeline stage and permits classification to continue with pending descriptions using their employer source. The summary still records budgetExhausted and interrupted work. Explicit cancellation remains incomplete; nonzero exits, worker/code/database errors and stale guarded writes remain failures. This does not override a GitHub job timeout or external cancellation.

The MongoDB queue reader materializes eight jobs per short indexed query and advances by _id. Each query finishes before inference; no database cursor remains open during multi-minute rewrites. Failed page reads still propagate as database errors. Source hashes, attempt counts and guarded updates retain the durable queue behavior. Interrupted work stays pending; transient item failures retry after one hour, up to three attempts. A changed source displays the latest employer text until its replacement passes. Model/policy changes do **not** automatically requeue published descriptions, unchanged historical records or old skipped records.

## Cache and diagnostics

Qwen has separate Actions keys for immutable assets and validated generated descriptions. The description cache lives in .cache/description-rewrites. Each signature includes the pinned model, protocol, messages/schema and complete input hash. A salary change or changed source structure requires a fresh rewrite; older compact decision caches cannot supply Qwen prose. Disk entries are validated before reuse. Only accepted complete outputs enter the cache, and the in-memory cache is bounded to 128 entries.

The v14 cache stores bounded source edits. Its signature binds these IDs to the exact original input. Earlier entries are isolated by protocol/version and Actions keys; the immutable model cache is reused. Summary artifacts and console results omit source/completion bodies and report configuration, warnings, token use, latency, memory, queue progress, and counts of model-edited versus copied items.

A separate description-rejections.json artifact contains at most ten rejected examples, capped at 64 KiB, with at most two samples per reason. A new rejection reason can replace a duplicate-reason sample when the set is full. Bounded raw completion previews survive partial JSON parsing and incomplete streams; failing section/item details are included when available. It excludes exception messages and configuration objects. The summary contains reason counts and the sample count, not those text excerpts. These examples follow the existing 14-day Actions artifact retention and repository access rules.

The generic publishing filter rejects missing, blank and empty-HTML employer descriptions before persistence. Historical empty-description records are hidden from public lists, detail pages, saved-job results and counts. An explicitly empty source cannot be replaced with generated display text. Scraper diagnostics retain filteredEmptyDescription, and raw dry-run captures remain available for inspection.

## Validation status and optional tools

The v13 GitHub run published two descriptions in five hours, with 28 token truncations, three timeouts and three other validation rejections, then left the pipeline incomplete at its normal budget. The earlier CursorNotFound did not recur. Measured performance is recorded in [BENCHMARK.md](BENCHMARK.md). No local tests, syntax/lint checks, model download, inference, database writes or workflow dispatch were performed for these v14 fixes, as requested. Regression cases were authored but remain unexecuted. The updated protocol, acceptance quality, throughput and classification handoff require pipeline validation.

Existing commands remain descriptions:preview (queue count), descriptions:rewrite (queue publication), and descriptions:benchmark (20 source jobs, no MongoDB). The optional native smoke test is test/qwenDescriptionWorker.integration.js; it requires predownloaded verified assets through DESCRIPTION_SMOKE_ASSET_DIR. The optional one-versus-four-slot comparison is separate from production defaults. Do not run these locally unless requested.

The full dry-run benchmark defaults to --model 9000 and the production bounded-edit client. Local source/output reports and resumable evaluations reject changed model/policy/source identities. Experimental trial prompting is documented separately in [TRIAL.md](TRIAL.md); it is not the production publication protocol. Windows speed and earlier model results do not establish Ubuntu throughput.
