# Local description generation on CPU

[LiquidAI LFM2.5-1.2B-Instruct QAD Q4_0](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct-GGUF) is the sole description rewriting model. Its immutable revision, 695,755,488-byte artifact, SHA-256 and llama.cpp CPU runtime are pinned in [model.json](model.json). No inference API is used. Pipeline classification prefers a validated current rewrite, falling back to original source; employer provenance remains preserved. Display text is stored separately in MongoDB description, with original sourceDescription, source hash and rewrite metadata preserved. Version 2 hashes retain raw source boundaries; migration refreshes metadata without queuing unchanged historical jobs. Only new or changed source versions are queued; unchanged legacy records receive no backfill.

The earlier model repeated the complete employer text as evidence, consumed thousands of output tokens and timed out. Policy v11 produces a compact source-fact plan and an overview reference. Each source fact has an ID; explicit responsibility, required/preferred, benefits and employment scopes are fixed before inference. Only facts with multiple allowed categories and up to four overview candidates enter the model prompt. Unlabelled facts that can only be additional details are copied directly, saving inference tokens. A tuple schema limits each unlabelled fact to conservative supported categories or additional details. Validation rejects uncertain heading assignments. The model organizes those facts and selects an overview; the renderer copies that source statement exactly. Detailed qualifications, numbers, salary, conditions and application facts are rendered from the exact employer statements. This is model-assisted editing and organization; most detailed wording is deliberately preserved. There is no word-count padding.

Publication requires a complete stream, one valid category per fact, unchanged requirement scope, an exact source overview and readable sections. HTML scripts are removed; headings and flattened PDF bullets are recovered. Mixed mandatory/preferred clauses, already structured employer HTML, unmanageable dense text, insufficient input and outputs with no structural gain retain their source. These automatic checks measure structure and source retention, and depend on accurate source-heading interpretation. Manual sample review remains necessary. Accepted content uses the existing escaped React heading/paragraph/list renderer.

## Actions budgets and resume

Scraping, GLiClass classification and description generation run in separate Actions workflows. The scrape job keeps its existing six-hour limit. Generation has a 350-minute job limit, a 315-minute step limit and a default 18,000-second (five-hour) total runtime budget including model setup. Its deadline also reserves two minutes before the job limit. An empty MongoDB queue skips model cache restore and startup. A separate Actions cache restores validated compact decisions across batches. The immutable checkpoint cache is independent of policy edits.

The GitHub workflow uses one job and one model server with four concurrent request slots, sharing a four-thread CPU configuration. Each slot retains an 8,192-token context, streaming and a 180-second request timeout. Output starts at 768 tokens; token-truncated responses can retry once at up to 1,536 tokens within the same request timeout and context budget. The server prompt cache is capped at 128 MiB. Local callers default to one slot. `JOB_DESCRIPTION_REWRITE_CONCURRENCY` selects the request concurrency; `JOB_DESCRIPTION_REWRITE_CPU_THREADS` selects the thread count. Both are capped at available CPUs, up to four. One producer reads the MongoDB cursor while bounded tasks overlap generation and guarded publication. The LFM chat template runs through llama.cpp Jinja. JOB_DESCRIPTION_REWRITE_MODE=off disables generation; JOB_DESCRIPTION_REWRITE_BUDGET_SECONDS overrides the runtime budget within the deadline. Each hosted job is limited to six hours: [GitHub limits](https://docs.github.com/en/actions/reference/limits).

LFM uses its own model and decision cache keys. Request signatures include the model manifest, so decisions from a different model cannot be reused. The 1.2B model uses fresh Actions model and decision cache keys. Switching the manifest does not rewrite already published jobs or automatically backfill old skipped records. This model switch was not tested locally; validation will be performed in the GitHub pipeline. See [historical capacity measurements](BENCHMARK.md); current-model throughput, peak memory and completion of the daily queue still need GitHub runner measurements.

The generic publishing filter rejects missing, blank and empty-HTML employer descriptions before persistence. The same rule hides historical empty-description records from public lists, detail pages, saved-job results and counts. Generated display text cannot replace an explicitly empty source. Scraper diagnostics include `filteredEmptyDescription`; dry-run snapshots retain raw entries for inspection.

The MongoDB source-hash queue survives runner shutdown. Interrupted work stays pending. Transient failures retry after one hour, up to three attempts; non-improving/preflight results are skipped. Conditional updates match source hash, active status, prior rewrite status and attempt count. A source change immediately displays the latest source until a replacement passes. Summaries record actual throughput, latency, worker memory, quality counters and remaining-queue estimates; source text and completions stay out of production diagnostics.

## Local verification

Existing commands remain descriptions:preview (read-only count), descriptions:rewrite (queue publication), and descriptions:benchmark (exactly 20 jobs; no MongoDB). Benchmarks retain original descriptions, generated plans, output, policy fingerprint, latency and peak memory. Resume rejects changed model/policy/source data.

To evaluate a running dry scraper without database writes:

    node --use-system-ca scripts/evaluateDryRunDescriptions.js --run-dir <dry-run directory> --catalog <scope.json> --output <evaluation directory> --watch

The catalog artifact must contain current source IDs and current dryRunFile paths under the backend. The evaluator archives completed company snapshots, visits one job per company per pass, and stores source/output comparisons under cases. Exact unchanged source and policy hashes reuse prior results; new source or policy hashes require generation. Per-case atomic saves survive interruption. Identical compact model requests reuse memory and disk plans across batches, but every displayed result is reconstructed and validated against its own full source. Disk plans contain numeric decisions and a request signature, never employer text. Changed, corrupt or invalid signatures fall back to inference. Each local batch defaults to five hours; exit 75 means the budget expired and its supervisor can resume. A stop-request.json file in the output directory requests cleanup. Empty and failed scrapes are reported separately; missing descriptions cannot become invented content. Full-catalog evaluation can take many batches.

The current native pilot and broader dry run are recorded in the workspace artifacts. Local Windows speed does not establish Ubuntu runner throughput. Improving layout and source retention is the goal; longer text does not guarantee AdSense approval. Google's [replicated-content policy](https://support.google.com/publisherpolicies/answer/11190248?hl=en) remains a separate publishing concern.

Transient Windows checkpoint replacement errors are retried with a bounded backoff. Unique staged files preserve complete prior checkpoints until a replacement succeeds; completed dry-run results survive a failed batch. Resume clears obsolete terminal error metadata while keeping source and model policy identities unchanged.

See [local verification results](VERIFICATION.md) for the LFM worker check, empty-description regression tests and the full-suite failure report.

Pipeline stage controls, success rules, GitHub handoffs and Local setup are documented in [Pipeline execution](../docs/PIPELINE.md). The former rewrite auto-run switch is retired.
