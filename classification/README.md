# Post-scrape classification with GLiClass

The sole job classification model is `knowledgator/gliclass-edge-v3.0`, pinned to revision `df03993a2ed98e5e4a0d2dd7efbbd105abe874cf` in [gliclass/model.json](gliclass/model.json). The public weights run on CPU; no hosted inference API or paid model is used.

Scrapers save source descriptions and mark new or changed inputs as `postClassification.status: pending`. They do not download or start a classification model. A separate [classification workflow](../.github/workflows/classify-jobs.yml) runs after successful rewriting in the default GitHub chain (or at its configured position in an admin pipeline), reads active MongoDB jobs, classifies the current validated rewritten description with fallback to original employer text, and writes results back using a source snapshot compare-and-set. Deterministic eligibility and source-quality checks use original employer text and fields even when the model receives a rewrite. A source edit during inference rejects the stale result. Owner leases prevent duplicate updates; completed unchanged inputs reuse cached predictions.

The four model labels are **Full-time Experienced**, **Full-time Fresher**, **Intern**, and **Contract**. Full descriptions use overlapping 512-token windows with 64-token overlap. Missing descriptions and descriptions over 262,144 UTF-8 bytes are skipped without claiming complete coverage. Source rules determine public eligibility and numeric experience. Raw GLiClass scores and disagreements remain in `postClassification.result`; these uncalibrated scores are not a measured accuracy percentage. Insufficient source evidence can produce `Unspecified`, and other explicit employment arrangements can produce `Others`.

Public listings and analytics expose only the four model categories. When source rules leave the category `Unspecified` and source-quality checks pass, the workflow uses the model prediction with `decisionSource: model_fallback`; numeric experience remains source based. Explicit source categories continue to override contradictory predictions. Complete authoritative legacy decisions reuse their saved model label at read time, consistently in Mongo filtering and API responses. Jobs without a supported category, or whose source-quality checks failed, remain in inventory but are excluded from public totals until classification succeeds. `comparison.logicJobType` retains the source-rule category so agreement remains a comparison against those rules.

`npm run db:repair-unspecified-job-types` previews a refresh of legacy unresolved decisions using validated cached predictions. Add `-- --apply` to persist the refresh and update dataset summaries. The repair checks the original source fingerprint and guards concurrent source and prediction edits; it does not call the model. Deploying the read-time fallback does not require this repair, and no production repair is performed by local tests.

`shadow` mode (standalone CLI default) records comparisons without making model results authoritative. `policy` mode writes the source-guarded classification and filter fields together. Classification can be retried independently of scraping. Pipeline execution uses `policy` mode. The workflow uses four shards on separate runners, requests four CPU threads per worker, and caps the effective count at the available CPU affinity and four threads. Its processing budget is five hours per shard with a six-hour job timeout. This is a configured budget, not a throughput guarantee; thread tuning needs measurement on the target runner.

## Diagnostics and skipped input

Every assigned job produces a row in `classification-<shard>.ndjson`, uploaded with its JSON summary. Rows contain job ID, company, short title, source identity, selected-description origin, input byte count, status and reason. They do not contain description bodies or evidence excerpts. Completed rows also report source-policy/public/model labels, agreement, an explicitly uncalibrated model score and fresh-inference measurements where available. Cached predictions contribute category counts but never reuse historical timing or RAM as measurements of the current run.

Missing input is recorded as `missing_description`; input above 262,144 UTF-8 bytes is `oversized_description`. Each reason has a separate summary counter. Use the diagnostic IDs to repair the employer source or scraper extraction, then run classification again: changed valid input is classified normally. Empty input cannot receive an invented label, and oversized input is not silently truncated. This change does not repair or requeue production records by itself.

Summary reports include resolved categories, public labels written in policy mode, model comparisons, uncertain decisions, source-quality issues, description origins, request counts, inference CPU/wall time, bounded latency buckets and worker peak RSS. Description origins cover all assigned inputs; category counters cover completed and cached decisions. Source-policy `Unspecified` is retained separately from public-label normalization; no category or confidence rules change. Uncertainty follows existing source-policy uncertainty or `Unspecified`, not a threshold on uncalibrated model scores. CPU usage is expressed as average CPU cores used during requests with measured CPU/wall time, not whole-host utilization. Latency buckets are mutually exclusive upper-bound ranges, not exact percentile measurements. Peak RSS includes Linux's OS process high-water mark or Windows' peak working set; other platforms retain the largest current observation.

### Reporting version 2 and eligibility review

`quality.modelAgreement` and `modelDisagreement` retain their original meaning: model label versus `comparison.logicJobType`, before model fallback. An unresolved source policy can therefore produce a false agreement flag even when the model and final labels match. The additive `modelFinalAgreement` and `modelFinalDisagreement` counters compare the model with the final resolved label; `modelFinalUnavailable` records missing comparisons, including completed/cached records from legacy shard summaries whose final-label comparison cannot be reconstructed. `modelFallback` counts decisions with `decisionSource: model_fallback`. These counters measure consistency, not accuracy or calibrated confidence.

Diagnostics now include `sourcePolicyJobType`, `modelMatchesFinalLabel`, `sourceQualityIssues`, and `reviewReasons`. Description origins describe the model input; source rules independently use original employer evidence. In the supplied 31 October run, replaying the saved labels gives 20,692 final-label matches, 1,164 differences, and 2,896 model-only fallbacks. The legacy 4,060 nonagreement flags remain unchanged. This replay does not rerun the model or repair saved jobs.

Explicit fresher vacancy titles can establish fresher eligibility when employer requirements do not conflict. Titles describing training or recruiting freshers, or explicitly excluding them, do not establish that eligibility. A fresher title conflicting with mandatory professional experience produces `conflicting_role_eligibility` and an uncertain `Unspecified` result. Existing occupation and internship guards remain in effect.

Clear trainee, apprentice, entry-level, new-graduate, and graduate-engineer vacancy titles establish a Full-time Fresher category when employer requirements do not require prior experience. Their zero-year filter default is marked `experienceBasis: entry_level_title`; employer-stated numeric experience remains separately stored and unspecified when absent. Titles describing recruitment, training or supervision of these applicants do not establish that eligibility. Explicit internship, contract and mandatory experience requirements retain precedence. A generic ambiguous title such as `Graduate` can still carry `entry_level_title_with_experienced_prediction` when its model fallback is Experienced. Source-quality failures also remain review reasons. `quality.reviewRequired` and `quality.reviewReasons` can overlap uncertainty and model-fallback counts and must not be added as disjoint groups.

Degree durations are excluded from professional-experience extraction. Explicit zero-experience eligibility for a fresher or entry-level vacancy takes precedence over an older graduation cohort; other cohort defaults remain in effect. Genuine mandatory experience conflicting with a fresher title and shared recruitment notices without role descriptions remain uncertain.

To refresh already flagged records without another model request, preview `node scripts/repairClassificationReviews.js` (optionally `--source=source-id`), then add `--apply` to persist eligible repairs. The command checks the original source identity, current native-inference fingerprint and complete cached prediction, and repairs only results that the current policy can resolve without review or source-quality issues. Concurrent source changes, active classification work and stale model caches are rejected. Unresolved source issues are skipped. The normal classification workflow also picks up the new runtime fingerprint and reuses valid native predictions.

Source recovery reads the bounded job-description sections on exact Flexsin and Tudip role pages. It excludes company background, navigation and application forms, retains role-specific experience metadata, and can replace Tudip's title-only source captions. Engineers India descriptions are isolated by advertisement number and title; their notice summaries establish only stated recruitment categories, without inventing individual role requirements. PlanetSpark cards are matched by title and native identity/location so another card's experience cannot enter the input. These readers reject ambiguous or mismatched identities. ACS discovery and detail enrichment also verify the recruiter employer before accepting a job.

For unresolved records with contaminated source descriptions, preview `node scripts/repairClassificationReviewSources.js` (optionally `--source=source-id`). Add `--apply` to replace validated source content and queue rewriting and classification. This command supports Engineers India, Flexsin, Tudip and PlanetSpark; it rejects stale source snapshots, current classification work and fresh source conflicts. It clears the old whole-page inferred experience field, invalidates the old rewrite/model result, and retains `Unspecified` until fresh processing finishes. It never reuses a prediction from a changed description. Run the source repair before the next rewrite/classification pipeline; the separate cached-decision repair handles fixes that leave source content unchanged.

Skills-and-competencies headings end the mandatory-qualification section. General client familiarity in that section does not establish prior professional employment; explicit applicant requirements such as “must have prior professional experience” still produce a fresher eligibility conflict.

Tudip and Flexsin now capture exact role descriptions during scraping, with four concurrent detail reads and verified response URLs. Failed detail reads retain their listing records with missing descriptions. Tudip no longer uses the role title as its description. Classification treats a title-only employer source as missing descriptive evidence, even if a previous rewrite exists; independent structured requirements remain usable. In policy mode, skipping such a record clears its obsolete inferred public category. Shadow mode preserves public fields.

The source repair command also scans active Tudip title captions that have no review flag or were skipped. Preview `node scripts/repairClassificationReviewSources.js --source=tudiptechnologies`; add `--apply` only after inspecting the preview. Recovery requires a verified exact role page, rejects in-flight processing and concurrent source edits, invalidates old caches, and leaves the public category Unspecified until the normal rewrite/classification pipeline completes. Real descriptions are preserved. Use the same command with `--source=flexsintechnologies` for the three flagged contaminated role descriptions.

Clauses welcoming both freshers and experienced candidates do not establish mandatory prior experience. Numeric, nonnumeric and conditional experience requirements still take precedence. The exact observed PlacementIndia employer alias `ACS Network & Technoloiges` is accepted for ACS ownership; other employers remain excluded. Preview `node scripts/repairClassificationReviews.js --source=acsnetworktechnologies` to check whether the saved ACS record resolves under these rules before applying a cached-decision repair. A genuinely contradictory WNS or other employer posting remains under review.

Runtime identities include the changed policy modules, so the next classification run reevaluates older saved decisions. Compatible cached native model predictions can still be reused. Do not delete classification records or mark missing descriptions valid to force a rerun. Data repair requires fresh, verified role-specific employer descriptions and the existing snapshot guards. The local source-repair preview prepared from the supplied archive is an ID manifest, not an apply-ready database repair plan.

The aggregate uses assigned partitions for `scanned`, with `scanCountBasis: assigned_partitions`. Repeated collection identity reads are reported separately as `identityScans`; four scans of 32,992 identities therefore do not appear as 131,968 classified jobs. Counts describe each worker's assigned records; they are not a point-in-time census if sources change during a run. Aggregate elapsed time is the longest shard processing time, while `workerSeconds` sums shard time. Peak RSS is the largest single-worker observation, with each runner's settings and peak retained under `workers`; separate runner RAM peaks are not summed.

Classification summaries include monotonic `timingMs` counters for source reads and partitioning (`sourceRead`), input preparation (`input`), lease writes (`claim`), the complete worker request (`modelRoundTrip`), policy resolution (`decision`), result/skip/failure writes (`save`), and diagnostic/progress callbacks (`reporting`). Model round trips include transport, tokenization and worker processing; Python's `inference.seconds` is a separate, narrower measurement and must not be added to those phase totals. Aggregate phase counters sum worker time across shards. Older summaries with no phase measurements leave those fields absent rather than inventing zero work. Per-job diagnostics include input, claim, model, decision and save timings; batched source reads and the diagnostic's own write are measured only at run level. Phase counters do not include worker startup or every small bookkeeping operation, and progress snapshots include reporting time from previously completed callbacks; the final summary includes the last callback.

The expected length warning is quiet only while tokenizing the complete document for window construction. Every inference window still passes the existing 512-token length check, with 64-token overlap and full-coverage validation. BPE tokenization cleanup is explicitly disabled when loading and decoding. Other dependency and inference warnings remain visible.

The runtime helper participates in the existing classification and native-prediction fingerprints. This runtime change invalidates older cache identities, so the first subsequent pipeline run can reclassify previously completed jobs; later unchanged runs reuse their results normally. It does not download a different model.

The 22 October 2026 diagnostics and CPU changes have not been tested locally or run through inference, as requested. New regression cases are authored but unexecuted; compatibility, performance and artifact contents remain pending pipeline validation.

## Source-quality and throughput repairs (6 November 2026)

Placeholder-only employer content such as `-`, `N/A`, `TBD`, or an empty description heading is missing evidence. A published rewrite cannot make a placeholder original sufficient. Independent employer qualification, responsibility and experience fields remain usable, including an explicit numeric zero. Policy-mode skips clear obsolete classification and public experience fields under the source snapshot guard; shadow skips preserve policy-owned fields.

An explicitly identified system-test-only vacancy stays `Unspecified` with `non_vacancy_test_posting`. Real System Test Engineer roles and internships restricted to selected students remain valid. Model-only categories gain `sparse_role_description` when their input is at most 100 UTF-8 bytes, and `model_fallback_without_majority` when the top uncalibrated class score is at most one half. These are review signals, not calibrated probability thresholds, and they do not invent experience or override an explicit source category. Entry-level vacancy titles that require prior professional experience retain employer bounds and gain `entry_level_title_with_required_experience` for review.

Flexsin and Bahwan preserve their native experience fields as `sourceExperienceRequired`. Phenom preserves native employment and experience metadata as source fields, separately from experience snippets inferred from description prose. Independently stated fields can support classification when a role description is unavailable; no synthetic description is stored. Genuinely absent source evidence remains unresolved until a successful source recovery and classification run.

`CLASSIFICATION_CONCURRENCY` accepts an integer from 1 through 8. The CLI and library default to 1; the Actions workflow uses 4. This overlaps database claims and saves around the existing serialized Python inference worker, while retaining owner leases, source compare-and-set guards and serialized diagnostic writes. Fatal reporting/read failures stop new admissions and drain already admitted work before shutdown. Time-budget and cancellation checks stop admitting new jobs; admitted work is allowed to settle.

Leases retain the ten-minute serial allowance and add five minutes for each possible request ahead in the worker queue. At concurrency four the lease is 25 minutes; at concurrency eight it is 45 minutes. This covers the existing five-minute request timeout without heartbeat writes, at the cost of longer recovery after an abandoned worker.

Worker summaries record `concurrency`, and aggregate `workers` retain each shard's setting. `timingBasis: summed_operation_durations` means phase durations include overlapping operations and may exceed wall-clock worker time. `modelRoundTrip` includes time waiting behind other requests in the serialized worker queue; `inference.seconds` remains actual inference work. These measurements must not be interpreted as disjoint percentages of wall time under concurrency.

These policy edits invalidate completed policy identities. Unchanged native prediction inputs can still reuse the saved native cache on the next run, without calling the model again. Existing production records are updated only when the repaired classifier runs; the local regression tests use isolated MongoDB instances. The historical missing-description count is not a promise that all 269 old records can be recovered.

## Local setup

From the backend directory, use Python 3.12 and install the CPU dependencies:

```powershell
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r classification/gliclass/requirements.txt
python classification/gliclass/download.py .cache/gliclass-model
$env:GLICLASS_MODEL_DIRECTORY = '.cache/gliclass-model'
$env:GLICLASS_CPU_THREADS = 'auto'
```

The downloader verifies the pinned model files against SHA-256 checksums. Set `GLICLASS_PYTHON` when using a dedicated Python executable. The existing local model and Python runtime under the workspace's `artifacts/gliclass-local-2026-10-10` can also be reused by setting those two paths.

With `MONGO_URI` configured, `npm run classify:jobs` starts the separate classification stage. **This command writes classification metadata to MongoDB even in shadow mode.** It is not a read-only dry run. It defaults to shadow; set `POST_SCRAPE_CLASSIFICATION_MODE=policy` to publish source-guarded fields. No production database run is part of the model cleanup.

| Setting | Default | Purpose |
| --- | --- | --- |
| `GLICLASS_MODEL_DIRECTORY` | Required locally; `.cache/gliclass-model` in Actions | Verified local model files |
| `GLICLASS_PYTHON` | `python` | Python executable |
| `GLICLASS_CPU_THREADS` | `auto` locally; `4` requested in Actions | Positive integer or `auto`; capped at available CPUs and four |
| `POST_SCRAPE_CLASSIFICATION_MODE` | `shadow` | `shadow` comparisons or `policy` updates |
| `CLASSIFICATION_SHARD` | `0` | Worker partition |
| `CLASSIFICATION_SHARD_COUNT` | `1` locally; `4` in Actions | Total partitions |
| `CLASSIFICATION_BUDGET_SECONDS` | `18000` | Processing budget per worker |
| `CLASSIFICATION_CONCURRENCY` | `1` locally; `4` in Actions | Maximum admitted jobs; integer from 1 through 8 |
| `CLASSIFICATION_SUMMARY_FILE` | `.cache/scraper-actions/classification-<shard>.json` | Progress summary |
| `CLASSIFICATION_DIAGNOSTICS_FILE` | Summary filename with `.ndjson` extension | Per-job outcomes without description bodies |

Description rewriting is a separate feature with its own model and workflow; classification prefers a current, validated rewrite and otherwise reads the original employer content. Its input hash includes the selected content and rewrite identity. See [Pipeline execution](../docs/PIPELINE.md). [Post-scrape tests](../test/postScrapeClassification.test.js) exercise partitioning, cache reuse, failure recovery, and source-change rejection using a temporary local MongoDB and fake inference responses.
